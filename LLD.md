# Low-Level Design (LLD)

## 1. Database Schema (MongoDB / Mongoose)

### 1.1 User Model
Stores authentication and profile data.
*   **_id**: ObjectId
*   **firstName**: String
*   **lastName**: String
*   **emailId**: String (Unique)
*   **password**: String (Bcrypt Hash)
*   **role**: String (Enum: `user`, `admin`)
*   **problemSolved**: Array of ObjectIds (Ref: `Problem`)
*   **resumeUrl**: String (Cloudinary URL)

### 1.2 Problem Model
Stores competitive coding challenges.
*   **_id**: ObjectId
*   **title**: String
*   **description**: String
*   **difficulty**: String (Enum: `easy`, `medium`, `hard`)
*   **tags**: Array of Strings
*   **visibleTestCases**: Array `{ input: String, output: String }`
*   **hiddenTestCases**: Array `{ input: String, output: String }`
*   **startCode**: Array `{ language: String, code: String }`
*   **referenceSolution**: Array `{ language: String, completeCode: String }`

### 1.3 Submission Model
Records user attempts on coding problems.
*   **_id**: ObjectId
*   **userId**: ObjectId (Ref: `User`)
*   **problemId**: ObjectId (Ref: `Problem`)
*   **code**: String
*   **language**: String
*   **status**: String (Enum: `accepted`, `wrong answer`, `compile error`, etc.)
*   **runtime**: Number
*   **memory**: Number
*   **passedTestCases**: Number
*   **totalTestCases**: Number
*   **createdAt**: Date (Used for Heatmap)

### 1.4 InterviewSession Model
Tracks ongoing and past AI Copilot interviews.
*   **_id**: ObjectId
*   **userId**: ObjectId (Ref: `User`)
*   **interviewType**: String (e.g., `MERN Stack Developer`)
*   **templateType**: String (Enum: `general`, `coding`)
*   **resumeUrl**: String
*   **jdText**: String
*   **status**: String (Enum: `in-progress`, `completed`, `discarded`)
*   **conversationHistory**: Array `{ role: String, text: String, codeContext: String, timestamp: Date }`

### 1.5 InterviewReport Model
Generated by Gemini at the end of an interview.
*   **_id**: ObjectId
*   **userId**: ObjectId (Ref: `User`)
*   **sessionId**: ObjectId (Ref: `InterviewSession`)
*   **overallScore**: Number (0-100)
*   **technicalScore**: Number
*   **communicationScore**: Number
*   **strengths**: Array of Strings
*   **weaknesses**: Array of Strings
*   **recommendations**: Array of Strings
*   **hireRecommendation**: String (`Strong Hire`, `Hire`, `Borderline`, `No Hire`)

## 2. API Contracts (Key Endpoints)

### 2.1 Start Interview Session
`POST /api/interview/session/start`
*   **Request Body**:
    ```json
    {
      "interviewType": "Frontend Developer",
      "templateType": "general",
      "jdText": "React, Redux, Tailwind requirements..."
    }
    ```
*   **Response (200 OK)**:
    ```json
    {
      "sessionId": "60d5ecb8b392...",
      "initialGreeting": "Hello! I have reviewed your resume. Let's begin..."
    }
    ```

### 2.2 Generate Follow-up (Conversation Loop)
`POST /api/interview/session/:id/generate-followup`
*   **Request Body**:
    ```json
    {
      "userAnswer": "I manage state using Redux Toolkit.",
      "codeContext": "const slice = createSlice(...)" // optional
    }
    ```
*   **Response (200 OK)**:
    ```json
    {
      "nextQuestion": "That's great. How do you handle async actions in Redux Toolkit?",
      "isTechnical": true
    }
    ```

### 2.3 Submit Code (Judge0 Execution)
`POST /submission/submit/:problemId`
*   **Request Body**:
    ```json
    {
      "code": "console.log('hello');",
      "language": "javascript"
    }
    ```
*   **Response (200 OK)**:
    ```json
    {
      "status": "accepted",
      "passedTestCases": 10,
      "totalTestCases": 10,
      "runtime": 0.045
    }
    ```

## 3. Class & Service Designs

### 3.1 AI Generation Services
Abstracted away from controllers, utilizing `@google/generative-ai`.
*   `questionGenerationService.js`: Defines prompt templates for initial questions based on Resume/JD matching.
*   `scorecardGenerationService.js`: Parses full `conversationHistory` and forces structured JSON output. Uses `json-schema` validation internally to catch hallucinations.

### 3.2 Problem Execution Utility
*   `problemUtility.js`: Contains `submitBatch` and `submitToken`. Uses base64 encoding to sanitize strings before sending to the configured Judge0 endpoint.

### 3.3 Auth & Middleware
*   `userMiddleware.js`: Reads `token` from `req.cookies`. Decodes JWT. Verifies token is not present in the Redis blacklist using `redisClient.get(token)`.

## 4. Security & Permissions

*   **Cookie Security**: JWT tokens are issued with `httpOnly: true`, `secure: true` (in production), and `sameSite: 'none'`. This prevents XSS attacks from extracting the token.
*   **Cross-Origin**: CORS is configured to accept credentials from the specific Vercel frontend URL, rejecting unauthorized origin requests.
*   **Admin Routes**: Endpoints like `/problem/create` and `/video/upload` require the JWT payload to contain `role: 'admin'`. This is enforced by `adminMiddleware.js`.
